Mendix storytelling animations

The design team handed me static comps for the 2025 mendix.com homepage. I pitched motion for them, then built it: a set of canvas animations, all running on one small helper I wrote to handle the plumbing.

From static comps to motion

The homepage redesign came to me as flat, polished comps: a starry hero, a partner section, an integrations row, a wall of customer logos. They looked great standing still. My job was to build them, and I saw a chance to make each section feel alive without getting in the way of the message.

So for each section I came up with a small idea that matched what it was saying. Partners became a hub with rings pulsing out to connected services. Integrations became a conveyor belt of apps plugging in one at a time. The hero’s stars started streaming toward you.

Every animation had to earn its place by saying the same thing as the copy next to it.

Apps plugging in

For the integrations section, a belt of apps steps along every two seconds. As each one lands under the connector, the hub card above bumps and glows, as if it just took the connection. Clicking cycles the color theme.

A hero you can steer

The hero’s starfield streams out from the center. Moving your pointer up speeds it up, and moving down slows it to a drift: a small reward for anyone who plays with it, invisible to everyone else.

One helper for every canvas

With several canvases on one page, the same chores kept coming up: sizing each one to its container, keeping it sharp on Retina screens, running a frame loop, and loading images first. So I wrote a small class to handle them once, and every animation was built on top of it.

It also handled the parts that are easy to forget:

  • Performance. Animations stop running when they scroll off-screen or the tab is hidden, so a long page doesn’t burn battery on things nobody can see.
  • Accessibility. With reduced motion turned on, each canvas draws a single composed still frame instead of animating.
  • Consistency. Every animation got timing, sizing and pointer input the same way, which made new ones quick to build.

Rebuilding it

The homepage has since been redesigned, so these animations live on here as rebuilds. I rewrote the helper from scratch as AnimationCanvas, a dependency-free library of about 1.6 KB, and recreated the animations as demos with generic icons in place of partner and customer logos.

  • Clock-driven, not timer-driven. The originals chained setTimeouts; the rebuilds work out every step, ease and bump from the animation clock, so they pause and resume cleanly.
  • Sized by the element, using ResizeObserver, so they work in any layout, not just full-width sections.
  • Live reduced motion, so turning the setting on mid-visit freezes them right away.

What I’d add next

For heavier scenes, I’d move drawing into a web worker with OffscreenCanvas, so animation never competes with the rest of the page for the main thread.
